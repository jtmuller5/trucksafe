# Trucksafe Labeler v5.6: Side-View Schema Simplification

> **Goal:** Remove the manufacturer-conditional sub-objects from `side_view`. Keep `fifth_wheel_manufacturer` as a single descriptive field for diagnostics, but stop conditioning engagement fields on it. The side-view safety signal collapses to two fields that have been reliable throughout iteration: `trailer_seated_flush` and `gap_between_apron_and_plate`.
>
> **Scope:** Audit run on the same 90-image set (seed 20260511). Scale-up to the archive is a separate decision after seeing v5.6 audit results.
>
> **What's NOT changing:** describe-not-judge architecture, inspection-level reframing (v5), `photo_matches_category` self-check (v5.5), pintle relaxed chains schema (v5.5), few-shot multimodal references (v5.4), fixed-band crop for lock_jaws, per-image detection crop for fifth_wheel and pintle_hook, Gemma 4 31B AWQ-4bit serving stack, vLLM endpoint, lock_jaws_underneath schema, rear_assembly schema.

---

## Why this change

v5.5 audit produced three findings that pulled in the same direction:

1. **Holland `washer_flush_against_body` is unreliable evidence.** v5.4 was firing `washer_flush=yes` on non-Holland fifth wheels (5 of 6 "yes" calls were on misidentified manufacturers). v5.5's drop from 6→1 was correction, not regression.
2. **Manufacturer ID itself is unreliable except for Jost.** User read of the v5.5 cohort: Jost is called correctly, but Holland vs Fontaine is approximately coin-flip. The diagnostic features (front pin, side pin, side handle position) are not consistently visible in archive photos.
3. **`trailer_seated_flush` and `gap_between_apron_and_plate` are reliable across iterations** and are the actual signals uncle uses to confirm the trailer is properly seated on the plate.

Manufacturer-conditional engagement evidence was architecture built to give per-manufacturer safety signals. Those signals turned out to either be unreliable (Holland washer) or never validated (Fontaine side pin, Jost — handoff already noted Jost engagement falls back to lock_jaws_underneath). Every conditional sub-object that doesn't drive the safety call is noise on the eventual fine-tune training signal. Cut them.

This is a **schema-honesty change, parallel to v5.5's pintle chains relaxation.** The schema is being aligned with what the inspection actually verifies and what the model can actually see.

## Schema changes

### `side_view` — strip manufacturer-conditional sub-objects

**Remove entirely:**

- `holland` sub-object (`front_pin_visible`, `front_pin_position`, `washer_flush_against_body`)
- `fontaine` sub-object (`side_pin_visible`, `side_pin_position`, `side_handle_visible`, `side_handle_position`)
- `jost` sub-object (`center_release_strap_visible`, `side_handle_visible`, `side_handle_position`)

**Keep as top-level fields:**

- `photo_matches_category` (from v5.5)
- `image_quality`
- `trailer_seated_flush` — primary safety signal
- `gap_between_apron_and_plate` — primary safety signal
- `fifth_wheel_manufacturer` (fontaine | jost | holland | other | unclear | not_visible) — kept as descriptive only, no downstream conditional logic depends on it

Update both `shared/schemas/side_view.json` and `side_view_describe_only.json` to remove the sub-objects. The Pydantic model for `SideView` needs the same treatment.

**Prompt change:** remove the manufacturer-decision-tree section ("front pin present → Holland; no front pin but side pin → Fontaine…"). Replace with a single line:

> *Report `fifth_wheel_manufacturer` if a manufacturer is clearly identifiable from a logo or distinctive feature. Otherwise report `unclear`. This field is descriptive only — your priority is `trailer_seated_flush` and `gap_between_apron_and_plate`.*

The intent of the demoted instruction is to take attention pressure off manufacturer ID so the model spends its budget on the two fields that matter.

### Side-view joint-pass criterion (new)

The downstream pass/fail for side_view is now:

`trailer_seated_flush == "yes"` AND `gap_between_apron_and_plate == "none"` (or whatever the "no visible gap" enum value is — confirm against the current schema).

Drop any joint-pass logic that referenced manufacturer or engagement sub-fields.

### Few-shot examples — consolidate manufacturer folders into a single `plate/` folder

The existing manufacturer-keyed folders (`side_view_holland/`, `side_view_fontaine/`, `side_view_jost/`) contain images that are still good exemplars — they show trailers properly seated with no visible apron gap. They were just labeled around the wrong lesson. Consolidate them.

**User-side task** (not for the rig agent):

1. Create `assets/few_shot_examples/side_view_plate/`.
2. Move images from `side_view_holland/`, `side_view_fontaine/`, `side_view_jost/` into `side_view_plate/`, renaming as needed to avoid collisions. Suggested naming: `plate_seated_01.jpg`, `plate_seated_02.jpg`, etc.
3. Delete the three old manufacturer folders.
4. Update `assets/few_shot_examples/captions.json`:
   - Remove all entries keyed under the old manufacturer paths.
   - Add new entries keyed under `side_view_plate/<filename>` with captions focused on the two retained signals. Example: *"Trailer apron seated flush against the fifth-wheel plate with no visible gap. This is the engagement-confirmed state for side-view inspection."*

**Rig-agent task:** update the prompt config for side_view evidence type to reference the new `side_view_plate/` folder instead of the three manufacturer folders. If the prompt builder iterates over a list of folders, the list shrinks from three to one.

Note for the agent: do not modify `captions.json` or move image files. If the `side_view_plate/` folder does not exist when the prompt builder runs, stop and surface to the user rather than proceeding with an empty exemplar set.

## Comparison report (v5.5 → v5.6)

The previous comparison report harness checked drift on `fifth_wheel_manufacturer`, `fifth_wheel_variant`, `hitch_latch_state`, `safety_chains_clipped_to_bar` and tripped a >10% drift threshold. v5.6's expected drift profile is different:

- **`fifth_wheel_manufacturer` drift is expected and not a threshold trip.** The field is being demoted; the model has explicit permission to call `unclear` more often. Report the drift count, but **do not stop-and-surface on this field**. A large shift toward `unclear` is the *intended* outcome.
- **`trailer_seated_flush` drift is the field to watch.** This field's reliability is the whole basis for the v5.6 simplification. If it drifts >5% on the yes-cohort (images flagged `photo_matches_category=yes`), stop and surface — that would mean removing the sub-objects somehow destabilized the primary signal, which would be surprising and important.
- **`gap_between_apron_and_plate` drift — same rule as `trailer_seated_flush`.** >5% on the yes-cohort = stop and surface.
- **`photo_matches_category` flag rate** — expect 18-25/90 (consistent with v5.5's 20/90). Significant deviation in either direction is worth a note but not a stop.
- **Lock_jaws and pintle metrics** — should be unchanged since their schemas didn't change. Confirm parity.

Report sections:

1. Schema integrity check (90/90 valid)
2. `photo_matches_category` flag rate, comparison with v5.5
3. Drift on primary side-view signals (`trailer_seated_flush`, `gap_between_apron_and_plate`), on the yes-cohort, with stop-and-surface threshold of 5%
4. Drift on `fifth_wheel_manufacturer` — informational only, no threshold
5. Lock_jaws parity check vs v5.5
6. Pintle parity check vs v5.5
7. Cost delta — expect slight reduction (shorter prompt, fewer fields per response)

## Definition of done

- All 90 audit images return valid v5.6 schema responses.
- `trailer_seated_flush` and `gap_between_apron_and_plate` show <5% drift on the yes-cohort vs v5.5's calls on the same images.
- Lock_jaws and pintle outputs are bit-for-bit identical to v5.5 on the same images (or, if there's any unexpected drift on fields that didn't change, surface immediately — that would indicate the side_view prompt change is leaking into other evidence types).
