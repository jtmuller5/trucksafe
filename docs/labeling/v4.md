# Trucksafe Labeler v4: Two-Pass Crop-Then-Describe

> **Goal:** Test whether Gemma 4 31B's native grounding can localize the coupling hardware well enough that a crop-then-describe pipeline produces more accurate descriptions than v3's whole-image describe.
>
> **Hypothesis:** v3 descriptions are sometimes geometrically wrong (e.g., reporting "obvious gap between apron and plate" when they're touching) because the coupling occupies ~10–15% of a 9MP portrait photo and the model confabulates from surrounding context. Cropping to the region of interest should remove the confabulation surface.
>
> **Not in scope yet:** Set-of-Mark overlays, fine-tuned detectors, multi-crop ensembles, single-pass box+describe. If v4 works, those are follow-ups. If v4 doesn't work, we revisit.

---

## What you're building

A v4 labeler that runs two passes per image, using the same Gemma 4 31B AWQ-4bit vLLM endpoint that v3 uses:

**Pass 1 — Localize.** Send the full image, ask Gemma 4 for a bounding box around the category-specific coupling hardware. Parse the box, expand it (margin), crop the original image to the expanded box.

**Pass 2 — Describe.** Send the crop through the existing v3 describe-only prompt set. Same prompts, same schema enforcement, no changes. The only thing different is the image.

The runner then assembles the production schema the same way v3 does: describe output + verdict from `--provenance archive_pass`.

---

## Subset

Run on the **same 90 audit images as v2 and v3** (seed 20260511, 30 per category). This gives you a clean three-way comparison: v2 → v3 → v4, same images, same provenance.

Output goes to `training/data/labels/audit-batch-03/`.

---

## Pass 1 prompt design

Per-category, because the model needs to know what to look for. Use Gemma 4's native bounding-box format — check `docs/gemma-finetune-deployment-guide.md` or the Gemma 4 docs for the current canonical format. The model returns normalized coordinates (typically `[y1, x1, y2, x2]` on a 0–1000 scale or 0–1; verify before parsing).

Three category-specific prompts (rough wording, refine as needed):

- **fifth_wheel:** "Locate the fifth wheel coupling assembly — the round metal plate on the tractor that the trailer kingpin sits in. Return a bounding box around the plate and the trailer apron above it. Output only the box coordinates."
- **lock_jaws:** "Locate the locking jaws of the fifth wheel coupling — the metal jaws that close around the kingpin. Return a bounding box around the jaws and the kingpin. Output only the box coordinates."
- **pintle_hook:** "Locate the pintle hook assembly — the hook on the rear of the truck and the lunette ring of the trailer. Return a bounding box including the hook, the lunette, the safety pin, and any visible safety chains. Output only the box coordinates."

Single output, no chain-of-thought, no description. Failure modes to handle:
- Model returns no box / refuses / returns malformed coordinates → log and **fall back to full image for Pass 2**. Mark this in the output JSON as `localization: "failed"` so we can audit how often it happens.
- Model returns a box that's >90% of the image area → treat as a refusal, same fallback.
- Model returns multiple boxes → take the largest, log it.

---

## Crop expansion

The model's box will probably hug the hardware tightly. We want enough context that the next pass can describe spatial relationships (apron sits above plate, chains cross under hook), so expand the box by **20% margin on each side**, clipped to image bounds.

If the box's aspect ratio is extreme (say >3:1), pad the short axis to a 4:3 or 1:1 aspect before resizing for the next pass — Gemma 4 handles square-ish crops better than narrow strips.

Save the crop as a separate file in `audit-batch-03/{category}/crops/{image_id}.jpg` so the HTML review can show original + crop side by side.

---

## Pass 2

Use the **exact same v3 describe-only prompts** without modification. Same schema enforcement. The crop replaces the full image; everything else is identical.

This isolates the variable. If v4 beats v3 on accuracy, we know cropping is the lever. If it doesn't, we know the problem is in the describe prompt itself, not the framing.

---

## Output structure

Per image, write a JSON like v3 but with new metadata fields:

```json
{
  "image_id": "...",
  "category": "fifth_wheel",
  "localization": {
    "status": "success",  // or "failed", "refused", "too_large"
    "box_normalized": [y1, x1, y2, x2],
    "box_pixels": [...],
    "expanded_box_pixels": [...],
    "aspect_corrected": true,
    "crop_path": "crops/..."
  },
  "describe_output": { ... },        // v3 describe-only schema, unchanged
  "production_schema": { ... },      // runner-assembled, unchanged
  "provenance": "archive_pass",
  "labeler_version": "v4",
  "elapsed_seconds_pass1": ...,
  "elapsed_seconds_pass2": ...
}
```

The audit log should aggregate localization success rate per category and total elapsed time, so we know the cost overhead vs v3.

## Comparison report

After the run, produce `comparison_v3_v4.md` in `audit-batch-03/`, structured like `comparison_v2_v3.md`. Specifically:

1. **Localization stats:** per-category success rate, refusal rate, too-large rate. Median/p95 box area as % of image.
2. **Per-field deltas** (same metrics as v2→v3):
   - `pintle_hook safety_pin_visible == true`
   - `fifth_wheel gap ∈ {none, minor, obvious}` distribution shift
   - `lock_jaws jaws_fully_closed == 'yes'`
   - `image_quality == 'poor'` rate per category (we expect this to drop on lock_jaws if cropping is helping)
3. **Elapsed time:** Pass 1 + Pass 2 vs v3 single-pass.
4. **HTML review:** extend the existing reviewer to show three columns per image — original (v3 input), crop with box overlay (v4 Pass 1 result), and v4 describe output. Same `:8770` server pattern: `audit-batch-03/review.html`.

---

## Success bar

**≥80% of bounding boxes correct on visual spot-check.** Specifically:

- Spot-check **30 boxes total** — 10 random per category — by overlaying the box on the original in the HTML reviewer.
- "Correct" means the box contains the relevant hardware and isn't dominated by irrelevant context (sky, asphalt, tires, mud flaps).
- If ≥24/30 (80%) pass, proceed with comparison report and recommendation.
- If <24/30, write up the failure modes (which category failed, what kind of misses) and stop before recommending scale-up. Don't iterate the prompt yourself — flag it.

The describe-quality comparison is secondary. If localization is solid, we expect description quality to improve; if it doesn't, that tells us the bottleneck is elsewhere.

---

## Implementation notes

- Reuse the v3 vLLM client and retry logic. Don't reimplement.
- One Gemma 4 31B endpoint serves both passes — no need to spin up a separate model.
- Run sequentially (Pass 1 for all 90, then Pass 2 for all 90) so a crash in Pass 2 doesn't lose Pass 1 work. Cache crops to disk between passes.
- The pintle-hook category is the highest risk for localization because the hardware is small relative to the rest of the rear-of-truck composition. Start your debugging there if things look off.
- If Gemma 4's bounding-box output format isn't what you expect from the docs, **don't fight it** — log the raw output for the first 5 images, look at it, then write the parser. Don't assume format.

---

## What to stop and ask before doing

- If Gemma 4's bounding-box capability is gated, requires a different model variant, or isn't exposed by the AWQ-4bit weights you're serving — stop, surface this, we'll pick a different detector (Grounding DINO is the fallback).
- If localization success on the first 10 images is below 50%, stop. Don't burn the full 90.
- If Pass 2 times balloon (>3x v3 single-pass per image), stop and discuss — that changes the scale-up calculus.

---

## Definition of done

1. `audit-batch-03/` exists with 90 labeled images and 90 crop files.
2. `comparison_v3_v4.md` written with the metrics above.
3. HTML reviewer updated to the three-column layout, accessible at the same `:8770` server path.
4. Localization spot-check (30 images) tabulated against the 80% bar.
5. A short recommendation at the end of the comparison report: **proceed to 7,500 with v4**, **fall back to Grounding DINO**, or **revisit describe prompts because cropping didn't help**.

Stop after that. No prompt iteration, no scale-up.
