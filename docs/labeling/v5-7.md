# Trucksafe Labeler v5.7: Fifth-Wheel Crop Padding

> **Goal:** Add vertical padding to the per-image detection crop for `fifth_wheel_coupling / side_view`. Diagnostic finding from v5.6 spot-check: at least 1-2 of the 5 drifted images were drifted because the crop was too tight — the trailer apron above the plate is the seating signal, and tight crops to the fifth-wheel hardware were trimming it off. v5.6's schema is held constant. This is a preprocessing fix, not a schema or prompt fix.
>
> **Scope:** Audit run on the same 90-image set (seed 20260511). The comparison baseline is v5.6, not v5.5 — the question is whether crop padding recovers confidence on the genuinely clear images while leaving truly ambiguous ones (dark, weird-angle) appropriately flagged.
>
> **What's NOT changing:** v5.6 schema (manufacturer sub-objects removed, flat `fifth_wheel_manufacturer`, two reliable signals `trailer_seated_flush` + `gap_between_apron_and_plate`), `photo_matches_category` self-check, v5.5 pintle relaxed chains schema, lock_jaws fixed-band crop, pintle per-image detection crop, prompts, few-shot exemplars, vLLM stack.

---

## Why this change

The v5.6 audit tripped a 24% drift threshold on `trailer_seated_flush` and `gap_between_apron_and_plate`. The drift was structured: 5 images flipped both fields toward `unclear` / `not_visible`. User spot-check at `:8770/labels/audit-batch-08/review.html` resolved that not all 5 are the same failure mode:

- **At least 1-2 images:** crop too tight — trailer apron context above the plate was trimmed off, removing the visual evidence the labeler needs to call seating
- **1 image:** genuinely too dark to assess — `unclear` is the honest answer
- **1 image:** `localize: refused` — detection didn't run, full image was used; this is a separate failure mode being deferred to a later iteration
- **Remaining 1-2 images:** unclassified from the spot-check

The seating call needs the **interface region** — apron + plate + a bit of context above and below — not the fifth-wheel hardware in isolation. Bounding-box detection on the fifth wheel is correctly localizing the hardware, but a hardware-tight crop is the wrong frame for this specific signal.

This is the kind of finding the describe-not-judge architecture and the comparison runner are good at surfacing: a preprocessing problem that looked like a schema problem until the drift was investigated.

---

## The change

In the existing fifth_wheel side_view crop function (single call site, per user — agent should locate from existing code), add vertical padding to the bounding box returned by detection before cropping.

**Initial parameters:**
- Top padding: **+30% of bbox height**, clamped to image edge
- Bottom padding: **+30% of bbox height**, clamped to image edge
- Horizontal padding: **0** (the seating signal is vertical; horizontal context isn't the issue)

If these specific values are wrong, tune in a second probe pass before running the full 90. Don't ship a full audit with a guessed padding parameter that wasn't probe-checked first.

**Constraint:** crop padding only applies to fifth_wheel `side_view`. Do not change cropping for:
- Pintle `rear_assembly` (working fine, 0 disagreements in v5.6 parity check)
- Lock_jaws `lock_jaws_underneath` (fixed-band 20-70% crop, not detection-based — leave alone)

The padding parameter should be a kwarg / config value, not a hardcoded constant, so future tuning is cheap.

---

## Implementation order

1. Agent locates the side_view crop function (user has indicated it's a single clean call site).
2. Agent adds a `vertical_padding_pct` parameter (default 0.30) to that function. The parameter expands the detection bbox vertically by that fraction of bbox height, clamped to image dimensions.
3. **Probe run on 3 of the 5 drifted images** — specifically the ones the user identified as crop-tight in the spot-check. Save before/after crop visualizations to `audit-batch-09/probe/` for visual inspection. Do NOT run the full 90 until user confirms the probe crops look right.
4. User reviews probe crops. Tunes padding if necessary (could request 0.20 or 0.40; first guess won't always be right).
5. Full 90-image audit run with the confirmed padding value.
6. Generate comparison report against v5.6 (not v5.5). Updated metric set below.
7. User spot-checks the same 5 drifted images plus any new flips at `:8770/labels/audit-batch-09/review.html`.

## Comparison report (v5.6 → v5.7)

The harness rule set changes because the diagnostic question has changed.

**Primary metric:** how many of the 5 v5.6 drifted images recover to v5.5's calls. If 3+ of the 5 recover, the crop-padding hypothesis is confirmed. If 0-1 recover, crop wasn't the dominant problem and the spot-check needs revisiting.

**Secondary metric:** drift on `trailer_seated_flush` and `gap_between_apron_and_plate` across the full 90, against v5.6. Expect drift in the **opposite direction** from v5.6 (toward more confident calls), specifically on the images where crop padding now includes the apron-plate interface.

**Stop-and-surface thresholds:**
- Manufacturer drift: **none** (informational only, schema didn't change between v5.6 and v5.7)
- `photo_matches_category` flag rate: deviation >5/90 from v5.6's 20/90 = stop and surface
- Pintle parity: any disagreement = stop and surface (the change is fifth_wheel-only; pintle outputs must be identical)
- Lock_jaws parity: any disagreement beyond the v5.6 vs v5.5 baseline of 1 = stop and surface

**Schema integrity:** 90/90 required as always.

## Definition of done

- All 90 audit images return valid v5.7 schema responses (90/90 schema integrity).
- 3+ of the 5 v5.6-drifted side_view images recover to confident calls on `trailer_seated_flush` and `gap_between_apron_and_plate`.
- The genuinely dark image stays `unclear` on those fields. (If padding "recovers" it to confident, that's a false win — the model is hallucinating from added context. Flag if this happens.)
- Pintle and lock_jaws outputs match v5.6 within the established parity tolerances.
- Comparison report written to `training/data/labels/audit-batch-09/comparison_v5_6_v5_7.md`.
