# Trucksafe Labeler v5.4: Pintle Schema Simplification + Few-Shot Multimodal Examples

> **Goal:** Two changes in one audit run:
> 1. Simplify the `rear_assembly` (pintle hook) schema to match the actual two-item inspection uncle taught us: (a) hitch latch fully closed, (b) safety chains clipped to bottom bar. Drop the cruft fields (`safety_pin_visible`, `lunette_ring_visible`, `hook_visible`, `safety_chains_crossed`) that have been carried forward from earlier iterations and aren't part of the real inspection.
> 2. Add curated few-shot multimodal reference images to the prompts for the fields that v5.2 couldn't move with text-only descriptions: `fifth_wheel_variant` on lock_jaws_underneath, `washer_flush_against_body` on Holland side_view, and the new pintle schema fields.
>
> **What's NOT changing:** describe-not-judge architecture, inspection-level schema reframing (v5), manufacturer-aware side_view fields (v5), fixed-band crop for lock_jaws (v5.2), per-image detection crop for fifth_wheel and pintle_hook (v5.1), Gemma 4 31B AWQ-4bit serving stack, vLLM endpoint.

---

## Schema change: `rear_assembly`

**Old fields (v5.2, to be dropped entirely):**
- `hook_visible` — cruft, presupposed by the photo existing at all
- `hook_latch_state` — replaced by `hitch_latch_state` (rename for accuracy; the latch is on the *hitch*, the hook is the assembly)
- `safety_pin_visible` — wrong field, was misidentified as the engagement check
- `lunette_ring_visible` — cruft
- `safety_chains_count` — keep
- `safety_chains_crossed` — cruft; not part of uncle's inspection

**New `rear_assembly` schema:**

```json
{
  "hitch_latch_state": "closed" | "open" | "unclear" | "not_visible",
  "safety_chains_count": 0 | 1 | 2 | "more_than_two" | "not_visible",
  "safety_chains_clipped_to_bar": "both_clipped" | "one_clipped" | "neither_clipped" | "unclear" | "not_visible"
}
```

Plus the inherited top-level fields: `inspection_type`, `evidence_type`, `image_quality`, `verdict`, `issues_detected` (maxItems:0 in describe-only schema), `factual_summary`.

**Two engagement checks, both required to pass:**
1. `hitch_latch_state == "closed"` (hook latch wrapped around the lunette ring)
2. `safety_chains_clipped_to_bar == "both_clipped"` AND `safety_chains_count == 2` (both chains physically clipped onto the bar/D-ring on the truck)

The runner doesn't apply these rules — verdict still comes from `--provenance`. But the describe schema captures the right fields for downstream verdict logic to apply these rules at training-data assembly time and at inference time on the phone.

**Note:** `safety_chains_crossed` is dropped despite being a real best-practice (crossed chains catch the tongue if the coupling fails). Uncle's inspection protocol doesn't include it, so it's not part of the truth. If a future iteration wants to add it back, it should be a separate evidence question with its own field — not folded back into `rear_assembly`.

`captions.json` maps each image to a diagnostic caption that names *what to look for*, not just the answer:

```json
{
  "lock_jaws/two_jaw_clear_01.jpg": "Two-jaw mechanism. Note the pair of curved metal fingers wrapping around the central kingpin.",
  "lock_jaws/single_bar_clear_01.jpg": "Single-bar mechanism. Note the horizontal bar positioned in front of the kingpin slot, no curved fingers.",
  "side_view_holland/washer_flush_01.jpg": "Holland with the washer flush against the plate body — pin fully retracted, coupling engaged.",
  "side_view_holland/washer_proud_01.jpg": "Holland with the washer extended away from the body — pin not fully retracted, coupling not properly engaged.",
  "pintle_hook/latch_closed_chains_clipped_01.jpg": "Hitch latch fully closed around the lunette ring. Both safety chains clipped onto the bottom bar with metal clips."
}
```

If `captions.json` or any expected reference image is missing from the curated set, stop and surface.

## Prompt structure per evidence type

For each evidence type, prompt becomes:

1. **Few-shot reference block:** show 2-4 reference images with captions, framed as "Here are reference examples of what to look for. Notice [the diagnostic feature]."
2. **Task block:** "Now describe the image below using the same vocabulary and structure."
3. **Schema directive:** existing structured-output instructions.
4. **The input image.**

### `lock_jaws_underneath`

Embed 4 reference images: 2 two-jaw + 2 single-bar exemplars. Replace v5.2's textual descriptions of the mechanisms with the few-shot block.

### `side_view` (Holland sub-branch)

Embed 4 Holland reference images: 2 washer_flush + 2 washer_proud. The proud examples are the calibration v5.2 was missing.

Fontaine and Jost sub-branches get 1 reference image each as a diagnostic anchor (both already >70% engagement; goal is hold-or-improve, not optimize).

### `rear_assembly`

Embed 2-3 reference images showing latch closed + chains properly clipped. If uncle provided a "what wrong looks like" exemplar (latch open or chain unclipped), include it; otherwise the positive-only set is fine for this round and we add the failure exemplar in v5.5 if needed.

The prompt should walk the model through the two-item inspection explicitly: "First, is the hitch latch closed? Second, how many safety chains are visible and are they clipped onto the bar?" Field order in the schema response mirrors inspection order.

## Success criteria

The experiment is **informational, not gating for the lock_jaws + Holland fields** (those experiments either work or they don't — both outcomes are useful for the writeup). The pintle schema change *is* gating: the new schema must validate at 100% and the inspection-relevant fields must be populated.

Outcome categorization:

- **Strong win:** Pintle schema validates at 100%, new pintle fields engage meaningfully (`hitch_latch_state` non-`unclear` ≥ 25/30, chains fields populated on most images). Lock_jaws variant ID ≥18/30 (60%). Washer outliers resolve cleanly. No regressions elsewhere. → **Scale on v5.4.**
- **Partial win:** Pintle schema valid, pintle fields engage. Lock_jaws variant ID improves to 10-17 non-`unclear` but doesn't hit 60%. No regressions. → **Scale on v5.4, accept lock_jaws still imperfect. Plan `fifth_wheel_overview` evidence type for v6.**
- **Pintle-only win:** Pintle schema clean, pintle fields engage. Lock_jaws variant ID doesn't move (4-6 non-unclear). → **Scale on v5.4 because the pintle simplification stands on its own merit. Lock_jaws variant ID confirmed as photo-supply problem, not prompt problem.**
- **No change or regression:** New pintle schema has integrity issues OR side_view manufacturer ID regresses meaningfully (≤16/30). → **Stop, surface. Roll back to v5.2 schema for pintle, investigate the regression.**

## Stop-and-ask thresholds

- `captions.json` or any expected reference image missing → stop, surface.
- Multi-image prompt format fails on the first probe → stop, surface. **Run a 5-image probe before the full 90** (1 per category: lock_jaws, side_view Holland, side_view Fontaine, side_view Jost, pintle). Verify schema integrity and that reference images visibly affect responses.
- Schema integrity below 90/90 → stop. The new pintle schema or reference images shouldn't break structured output; if they do, something's wrong with prompt assembly.
- Elapsed time more than doubles v5.2 (>16 minutes) → stop, discuss. Scale-up cost calculus changes.
